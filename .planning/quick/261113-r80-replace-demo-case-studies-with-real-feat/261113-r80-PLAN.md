# Quick Task 261113-r80: Replace demo case studies with real feature playbooks via data migration

The 11 seeded case studies ("Black Friday Retailer 2x", "17% of monthly revenue in 6 hours",
"A/B Testing Success", ...) are invented demo content. The case study page also hardcodes fake
testimonials ("The A/B testing tools have been game-changing", "post-purchase content"), and the
homepage feature grid advertises things the app does not do (segmented offers, A/B testing).

## Content rules

- Every case study is a playbook built on a real, shipped Pricing Schedule feature (verified in
  `pricing-intelligence/web`: KB §15, §18, §22–27, `CampaignSyncRun`, `CampaignReportService`,
  `Agent::CampaignDraft`, `Campaign::SelfHelp::UNDO_END_WINDOW = 180.minutes`).
- No invented customers and no invented percentages. The stats are capability facts.
- The only quotes are verbatim Shopify App Store reviews (checked against the raw page HTML),
  attributed to the store and labeled as reviews.

## Tasks

1. Schema migration: add `primary_stat_label`, `secondary_stat_label`, `key_results` (text),
   `quote` (text), and `quote_attribution` to `case_studies`. This is add-only, so it is safe
   during a rolling deploy.
2. `db/data/case_studies.yml`: 7 playbooks (Black Friday scheduled sale, Sidekick AI assistant,
   collection clearance + product sync, vendor price increase, price-range flash sale,
   campaign controls + undo + support, campaign reports).
3. Data migration: purge CaseStudy image attachments, clear `case_studies_products`, delete all
   case studies, and insert the YAML. Irreversible.
4. `db/seeds.rb` loads the same YAML (one source).
5. Views:
   - `case_studies/show`: data-driven stat labels; remove all hardcoded quotes and the
     "long game" section (this also fixes the nil `product_features.downcase` crash);
     render `key_results` and the review quote only when present; fall back to `image_url`.
   - `home/index`: case study section copy, card stat + label, `image_url` fallback, and a
     feature grid that lists only real features.
   - Admin form, index, and controller permit/label the new fields.
6. `CaseStudiesController#show`: an unknown id gets a 301 to the index, because the old demo
   URLs are indexed.
7. Request spec for the case study show page, the redirect, and the YAML shape.

## Verify

- Migrations run up in dev and test; dev shows the 7 new records.
- `bundle exec rspec` passes; rubocop is clean on the changed Ruby files.
- grep finds no fake quotes or demo case study names left in app/ or db/seeds.rb.
