## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin browser → `Admin::BlogsController#update` | Authenticated admin submits form params; `Admin::BaseController` (Devise + admin flag) is the only gate |
| Public browser → `BlogsController#show` | Fully untrusted, unauthenticated read path; must have no write access to the new columns |
| Admin-authored `body` HTML → `blogs.body` column | Author-controlled markup crosses into storage via `before_save :sanitize_body` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Elevation of Privilege | `toc_enabled` write path | mitigate | Permit `toc_enabled` only in `Admin::BlogsController#blog_params`, which inherits `Admin::BaseController`'s Devise + admin-flag gate. Task 1 acceptance asserts `grep` finds no `toc_enabled` reference in `app/controllers/blogs_controller.rb` or `app/controllers/api`. |
| T-01-02 | Tampering | `toc_overrides` jsonb mass assignment | mitigate | Deliberately NOT added to strong params in this phase. An unvalidated jsonb structure with no consumer is pure attack surface; Phase 4 (ADMIN-02) permits it only alongside anchor-key and string-value validation. Task 1 acceptance asserts its absence from the permitted list. |
| T-01-03 | Tampering | `id` attribute persisted into `blogs.body` (DOM clobbering) | mitigate | `id` stays out of `Blog::ALLOWED_ATTRIBUTES` (D-03). Task 2 adds an executable invariant asserting both that a submitted `id="evil"` is stripped on save (Blog and Article) and that the allowlist constant itself excludes `"id"`. |
| T-01-04 | Denial of Service | Migration table rewrite on a large `blogs` table | accept | `add_column` with a constant default is metadata-only on PG 11+/Rails 8. Task 1's before/after `pluck` diff proves no rewrite occurred on the actual dataset; a non-empty diff halts the plan. |
| T-01-05 | Information Disclosure | New columns leaking into `api/v1/blogs/show.json` | accept | The jbuilder template enumerates fields explicitly (`json.content_html @blog.body`, `json.faq`); it never serializes the full attribute hash, so new columns cannot appear.
