<objective>

Create `app/models/blog/table_of_contents.rb` defining `Blog::TableOfContents` (nested inside `class Blog` so Zeitwerk resolves the namespace from `app/models/blog.rb`). Follow RESEARCH.md Pattern 1's reference implementation, which was executed and verified against this repo's bundle.

Required behavior, in order:

1. `self.call(sanitized_html)` parses `sanitized_html.to_s` with `Nokogiri::HTML5.fragment` and returns a derived instance. Use `Nokogiri::HTML5` explicitly, never bare `Nokogiri::HTML`, never `Nokogiri::HTML4::DocumentFragment.parse`, and never `Rails::Html::SafeListSanitizer` — that constant is the HTML4 variant and its round-trip decodes `&nbsp;`/`&mdash;` to literal characters, which changes response bytes on every entity-bearing post and breaks LAYOUT-04 (RESEARCH.md Pitfall 1, verified).

2. Parse ONCE. The same fragment is mutated in place and re-serialized. Do not parse a second time to extract entries — two passes can disagree on anchor assignment.

3. Iterate `fragment.css(HEADING_SELECTOR)` with the index. `"h2, h3"` returns document-order H2/H3 only, which satisfies D-01 (H1 and H4-H6 excluded) and D-10 (an orphan H3 preceding any H2 is still included, flat, with no hierarchy-validity filter).

4. Base slug = `node.text.parameterize`. When it is blank, fall back to `"section-#{index + 1}"` — the D-02 positional fallback. This path is NOT an edge case: `parameterize` returns `""` for emoji, CJK, Cyrillic, and punctuation-only text (RESEARCH.md Pitfall 3, verified). When it is present, truncate the base to `MAX_SLUG_LENGTH` (80) FIRST and then strip a trailing hyphen left behind by truncation, so anchors never end in `-` (Pitfall 4). Truncate before uniqueness allocation, never after.

5. Allocate the final anchor with a used-set probe, NOT a per-base occurrence counter. Maintain a set of already-issued final anchors; start at `"#{ANCHOR_PREFIX}#{base}"`; while that candidate is already issued, increment a counter (starting from 1, so the first suffix is `-2`) and re-probe `"#{ANCHOR_PREFIX}#{base}-#{counter}"` until free; record and return. A `Hash.new(0)` counter keyed on the base slug produces verified duplicate anchors for the sequence `Getting Started`, `Getting Started`, `Getting Started 2`, and for a real heading `Section 5` colliding with a positional `toc-section-5` fallback (RESEARCH.md Pitfall 2, both reproduced). Duplicate ids make every deep link past the first resolve to the wrong section and will make Phase 3's scroll-spy highlight the wrong entry.

6. Assign `node["id"] = anchor` (Nokogiri escapes the value on serialization) and push an `Entry` struct with `level` (from `node.name`, an Integer 2 or 3), `anchor`, `label_html`, and `text` (`node.text.strip`).

7. `label_html` implements D-08: pass `node.inner_html` through `ActionController::Base.helpers.sanitize(..., tags: LABEL_TAGS, attributes: LABEL_ATTRIBUTES)` so a heading like `Getting <code>Started</code> Fast` yields a label that keeps the `<code>` element. `LABEL_TAGS` is a deliberately narrow subset of `Blog::ALLOWED_TAGS` — do not widen it to include `img`, `table`, or block elements. Use the `ActionController::Base.helpers.*` form the repo already uses in `Blog#seo_description`.

8. `#to_html` returns `fragment.to_html` — a plain `String`. Do NOT call `.html_safe` inside this class; marking the string safe is the helper's responsibility in plan 01-04, where the justification comment lives next to the trust decision.

9. This class performs NO sanitization of the body itself and adds NO third sanitizer pass over the document. It only adds `id` attributes whose values are `parameterize` output constrained to `[a-z0-9-]`. Do not call `sanitize` on the whole fragment — that would strip the `id` you just set, since `id` is deliberately absent from `Blog::ALLOWED_ATTRIBUTES`.

Style: frozen SCREAMING_SNAKE constants at the top in the `%w[...].freeze` form used in `app/models/blog.rb:7-8`; no base class, no mixin, no dry-rb; `private` keyword with helper methods grouped below it; short `#` comments above surprising lines only (no RDoc/YARD); 2-space indent, rails-omakase.

Separately, add `gem "nokogiri"` to the top-level group of `Gemfile` (not `:development, :test` — it is a runtime dependency) with a one-line `#` comment in the file's existing style, then run `bundle install`. This phase makes Nokogiri a first-class application dependency rather than an implementation detail of `rails-html-sanitizer`. The expected `Gemfile.lock` diff is the single line `nokogiri` added under `DEPENDENCIES`; the resolved version must stay `1.18.10`. If `bundle install` proposes any version change to any gem, revert the Gemfile edit and report — Nokogiri is already loadable without the declaration.
