    Create `app/views/blogs/_toc_sidebar.html.erb`. It takes one local, `entries`. Whitespace in this file is unconstrained — it only ever renders on the TOC-on branch, which has no golden master.

    Structure, outermost to innermost:

    1. Self-guard the whole partial with `<% if entries.any? %>` / `<% end %>`, matching `_faq_section.html.erb`.

    2. Wrapper `<div>` — this is the grid item AND the sticky element. Exact class list:
       `hidden lg:block lg:col-start-2 lg:row-start-1 lg:self-start lg:sticky lg:top-8 lg:max-h-[calc(100vh-4rem)] lg:overflow-y-auto`
       Every one of these is load-bearing:
       - `hidden lg:block` — D-02/D-03: nothing at all below 1024px. `display: none` removes it from layout AND the accessibility tree, which is the only server-renderable way to satisfy "no sidebar, no layout shift" with no viewport info at render time.
       - `lg:col-start-2 lg:row-start-1` — D-01: renders visually right while sitting BEFORE the article in DOM order (WCAG 1.3.2 reading sequence). Do not use flexbox `order` to achieve this.
       - `lg:self-start` — MANDATORY. Grid items default to `align-self: stretch`, so without it the sidebar is already the full row height and `sticky` has nowhere to travel. This is a silent failure: DevTools shows `position: sticky` and `top` set, and nothing happens.
       - `lg:max-h-[calc(100vh-4rem)] lg:overflow-y-auto` — Pitfall 8: on a 15-heading post the sticky column would otherwise have its bottom permanently cut off. Overflow on the sticky element ITSELF is harmless; only clipping ancestors break sticky.
       Do not add any background fill, border, shadow, rounding, or padding that reads as a card — UI-SPEC "Visual Hierarchy" makes the sidebar deliberately surface-less so it does not compete with the article.

    3. `<nav aria-label="Table of contents">` — that exact string, sentence case, verbatim from A11Y-01. Do not write "Table of Contents navigation" and do not use `aria-labelledby`.

    4. Visible label as a `<p>`, not a heading: text `Table of Contents` (title case, D-05), classes `text-sm font-semibold uppercase tracking-wide text-gray-900 mb-4`. A sibling `<h2>` here would pollute the very heading outline the TOC describes.

    5. `<ol role="list" class="list-none space-y-2 pl-0">`. `role="list"` is required because `list-none` sets `list-style-type: none`, which drops list semantics in Safari/VoiceOver. Flat list only — no nested `<ol>` (that is TOCV2-01, out of contract).

    6. Iterate `entries.each do |entry|` emitting one `<li>` per entry. The `<li>` carries `pl-4` when `entry.level == 3` and nothing otherwise (D-06 indent half). Write both branch values as complete literal class strings inside a ternary — Tailwind v4 scans source files as plain text and cannot resolve concatenated or interpolated class fragments.

    7. Inside each `<li>`, a `link_to "##{entry.anchor}"` with a block. Class list, composed from complete literal strings:
       - always: `block no-underline transition-colors rounded-sm`
       - when `entry.level == 3`: `text-sm text-gray-500` (the "smaller and lighter" half of D-06)
       - otherwise: `text-base text-gray-900`
       - always: `hover:text-pink-600 focus-visible:text-pink-600 focus-visible:ring-2 focus-visible:ring-pink-600 focus-visible:ring-offset-2`
       Hover alone fails SC 2.4.7, which is why the `focus-visible` pair is not optional. Do NOT suppress the browser's native focus outline. Do NOT apply any pink color at rest — a column of 10+ accent links would invert the visual hierarchy. Do NOT emit `aria-current` or any active/current styling; that is Phase 3's and cannot be computed server-side.

    8. The link's block body renders `sanitize(entry.label_html, tags: %w[strong em code], attributes: [])`. This is Pitfall 4's fix: `Blog::TableOfContents::LABEL_TAGS` permits `a`, so a heading containing an inline link would otherwise produce a nested `<a>` inside the sidebar's own `<a>`, which the HTML parser resolves by closing the outer anchor early and silently breaking the TOC link. The narrower allowlist drops the `<a>` while keeping its text. Do not narrow `LABEL_TAGS` in the PORO — that is Phase 1's contract D-08 and `label_html` has Phase 4 consumers.

    Explicitly out of contract for this file: any mobile markup, dropdown, or `<details>` element; a "back to top" control; reading-time; numbered entries; icons or an icon library; any new npm/gem dependency.
  </action>
