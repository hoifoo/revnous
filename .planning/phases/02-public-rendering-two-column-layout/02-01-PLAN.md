<objective>
Build the server-side data layer for the TOC sidebar: one helper call that returns both the anchor-injected article HTML and the filtered, threshold-checked entry list, plus the heading permalink affordance injected into the same Nokogiri fragment.

Purpose: The view (Plan 02-02) needs three facts from one parse — the HTML to render, the entries to list, and whether the TOC renders at all. Computing them separately would mean two Nokogiri parses (forbidden by Phase 1 D-03) and duplicate threshold logic.

Output: `BlogsHelper#blog_article` returning an `ArticleContent` value object, with hide-override filtering (D-09/D-10), the 3-entry suppression threshold (TOC-04/D-12), and permalink decoration (INTX-04/D-15). The existing `blog_body_with_toc_anchors` stays in place and untouched so `show.html.erb` and every existing spec keep working — Plan 02-02 removes it when it switches the call site.
</objective>

    - For a TOC-on blog with 3+ headings, the returned `html` contains `class="toc-permalink"` exactly once per H2/H3 heading (count via `scan`)
    - Each injected anchor's `href` equals `#` plus its own heading's `id` — for a heading with `id="toc-intro"` the html contains `href="#toc-intro"`
    - Each injected anchor carries `aria-label="Permalink to Intro"` for a heading whose text is `Intro`
    - The glyph lives in an inner `<span aria-hidden="true">#</span>`; `aria-hidden` never appears on the `<a>` itself
    - Entry labels are uncontaminated: no entry's `text` ends with `#`, and no entry's `label_html` contains `toc-permalink`
    - The heading's opening tag is untouched: html still contains the literal `<h2 id="toc-intro">`
    - Entity preservation: a heading body containing `&amp;` still contains `&amp;` in the returned html (Nokogiri must not mangle it)
    - Suppressed branch: a TOC-on blog with only 2 headings returns html containing NO `toc-permalink` occurrence
    - H1 / H4-H6 and any heading without a `toc-` id get no permalink
  </behavior>

  <action>
    Add a private `decorate_permalinks!(fragment)` in `app/helpers/blogs_helper.rb`, below `visible_toc_entries`, and call it from `blog_article` on the line immediately before the final `ArticleContent.new(...)` return — that is, AFTER the `visible.size < MIN_TOC_ENTRIES` guard, so suppressed posts get no permalinks.

    Ordering is the whole point of this task: `Blog::TableOfContents#derive!` computes `label_html` from `node.inner_html` and `text` from `node.text.strip` inside its heading loop. Injecting the permalink before or during that loop leaks a literal `#` into every sidebar entry and into `entry.text` (reproduced in RESEARCH Pitfall 5). Because `Blog::TableOfContents.call` already ran `derive!` by the time `blog_article` has the instance, a plain second traversal of `toc.fragment` is safe. Do not add this behavior to `app/models/blog/table_of_contents.rb` and do not move it inside `derive!`.

    Implementation shape:
    - Select nodes with `fragment.css("h2[id], h3[id]")`.
    - Skip any node whose `id` does not start with `Blog::TableOfContents::ANCHOR_PREFIX` — reference the constant, never a hardcoded `"toc-"` literal.
    - Build the accessible name as `ERB::Util.html_escape("Permalink to #{node.text.strip}")`. Heading text is author-controlled; escaping before it enters an attribute is the V5 output-encoding control and is what keeps Brakeman satisfiable.
    - Append with `node.add_child(...)` passing an HTML string for an `<a>` with `class="toc-permalink"`, `href` of `#` plus the node's own `id`, and `aria-label` of the escaped name; its only child is `<span aria-hidden="true">#</span>`. `aria-hidden` goes on the inner span ONLY — the `<a>` is focusable per D-15 and UI-SPEC, and `aria-hidden` on a focusable element is an ARIA violation.
    - `add_child` accepts an HTML string, parses it in context, leaves the heading's opening tag untouched, and preserves entities such as `&amp;` — all verified in RESEARCH Pattern 6.

    Extend the existing `# SECURITY:` block comment above the helper methods so it also covers permalink injection: state that the second downstream mutation adds only an app-authored `<a>` whose `href` is the same `parameterize`-derived `toc-` anchor and whose `aria-label` is HTML-escaped heading text; no author markup is reintroduced and no sanitizer allowlist is widened. Brakeman flags `.html_safe`, and this in-line argument is how this project has chosen to answer it.

    Do not add a `class="group"` attribute to headings, do not emit any inline `style`, and do not add the hover CSS here — Plan 02-02 owns `application.tailwind.css`.
  </action>
