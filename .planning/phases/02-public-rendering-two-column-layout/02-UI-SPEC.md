# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** the TOC-**on** two-column blog show page only. The TOC-off page is frozen by `spec/requests/blogs_golden_master_spec.rb` and this contract must not change a single byte of it (LAYOUT-03/LAYOUT-04).

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | — (not used) |
| sm | 8px | Vertical gap between TOC entries (`space-y-2`) |
| md | 16px | H3 entry left indent (`pl-4`, D-06); sidebar label bottom margin (`mb-4`) |
| lg | 24px | — (reserved; not used) |
| xl | 32px | Sticky sidebar top offset (`lg:top-8`, D-07); heading `scroll-margin-top` (`prose-headings:scroll-mt-8`) |
| 2xl | 48px | Grid column gap between article and sidebar (`lg:gap-12`); article H3 top margin (`prose-h3:mt-12`, D-14) |
| 3xl | 64px | Sticky sidebar max-height subtraction (`max-h-[calc(100vh-4rem)]`) |
| 4xl | 80px | Article H2 top margin (`prose-h2:mt-20`, D-14) — reinforces section breaks now that a sidebar tracks them |

**Fixed layout dimensions** (not spacing tokens, but locked here so the planner does not invent alternatives):

| Dimension | Value | Source |
|-----------|-------|--------|
| Sidebar column width | **256px (16rem)** — fixed track, never a fraction | D-04 |
| Article column track | **`minmax(0,1fr)`** — never bare `1fr` | RESEARCH Pitfall 2 (`<pre>`/`<table>` blowout) |
| Grid template | `lg:grid-cols-[minmax(0,1fr)_16rem]` | D-01 (sidebar right) + D-04 |
| Two-column activation | `lg` breakpoint / **1024px** only | D-02 |
| TOC-on page container | **`max-w-5xl`** (TOC-off stays `max-w-4xl`) | See ⚠️ below |

⚠️ **`max-w-5xl` is a recommendation carried from RESEARCH Open Question 1 (assumptions A6/A7), not a user-locked decision.** Arithmetic: 1024px container − 64px padding − 256px sidebar − 48px gap = **656px** article column, so the typography plugin's own `max-width: 65ch` (~620px) binds with ~36px slack — which is how D-13 gets satisfied *by prose* rather than incidentally by the grid. At `max-w-4xl` the article column drops to 528px, narrower than 65ch, and D-13 becomes meaningless. **This widens the TOC-on hero, title, image, and excerpt too** (they share the line-28 container). Confirm at the UI review gate before implementation; it is one class and trivially reversible.

Exceptions: none — every declared value is a multiple of 4.

## Typography

Declared scale for this phase (3 sizes, 2 weights):

| Role | Size | Weight | Line Height | Applies to |
|------|------|--------|-------------|------------|
| Label | 14px (`text-sm`) | 600 (`font-semibold`) | 1.43 (20px) | Sidebar visible heading "Table of Contents" — uppercase, `tracking-wide` |
| Entry (H3) | 14px (`text-sm`) | 400 | 1.43 (20px) | Nested TOC entries — smaller **and** lighter per D-06 |
| Entry (H2) | 16px (`text-base`) | 400 | 1.5 (24px) | Top-level TOC entries |
| Body | 18px | 400 | 1.7778 (32px) | Article body — **inherited unchanged** from `prose-lg` |

**Article heading sizes are inherited, not redeclared.** `prose-lg` ships h2 at 30px and h3 at 24px `[VERIFIED: node_modules/@tailwindcss/typography/src/styles.js]`. This phase changes **only their top margins** (D-14). Any plan task that alters an article heading `font-size` is out of contract — that would break the TOC-off/TOC-on visual kinship and is not what LAYOUT-03 authorizes.

**Permalink glyph** inherits its heading's size and weight; it introduces no new type token.

**Reading measure (D-13):** implemented by **dropping `max-w-none`** in the TOC-on branch so the plugin's own `max-width: 65ch` applies. Do **not** add a `max-w-prose` or `max-w-[65ch]` utility — that duplicates a value the plugin already owns. Note: CONTEXT.md D-13 says "~75ch"; the installed plugin value is **65ch** `[VERIFIED: styles.js:1414]` — 65ch is the contract.

**Sidebar label is a `<p>`, not a heading.** The article's own H2s are what the TOC lists; a sibling `<h2>Table of Contents</h2>` would pollute the very heading outline the TOC describes.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (white) | Page background, article surface, **and the sidebar surface — the sidebar gets no background fill, no border, no card treatment** |
| Secondary (30%) | `#111827` (gray-900) / `#6b7280` (gray-500) / `#e5e7eb` (gray-200) | gray-900: H2 TOC entries + article headings. gray-500: H3 TOC entries (the "lighter" half of D-06) + the resting permalink glyph. gray-200: existing horizontal rules only |
| Accent (10%) | `#db2777` (pink-600) | See reserved-for list below |
| Destructive | not applicable | **This phase has no destructive action.** Do not introduce a red token |

**Accent reserved for — exhaustively, in this phase:**

1. TOC entry link `:hover` and `:focus-visible` text color (D-08)
2. Permalink `#` affordance `:hover` and `:focus-visible` text color (D-15)

Nothing else. TOC entries are **gray at rest, pink only on hover/focus** — a sidebar of 10+ pink links would put the accent well past 10% and flatten the hierarchy D-06 establishes. The active-entry treatment is **reserved for Phase 3** (INTX-02/A11Y-01's `aria-current` half); Phase 2 must not pre-paint an "active" state it cannot compute.

**Contrast (verified, WCAG 2.1 AA):**

| Pair | Ratio | Verdict |
|------|-------|---------|
| pink-600 `#db2777` on white | 4.60:1 | PASS (normal text ≥ 4.5:1) |
| gray-500 `#6b7280` on white | 4.83:1 | PASS — safe for 14px H3 entries |
| gray-900 `#111827` on white | 17.4:1 | PASS |

**Hover is not the only signal.** TOC links must also carry `focus-visible` styling (color + visible ring/outline), because color-on-hover alone is unreachable by keyboard and fails SC 2.4.7.

## Copywriting Contract

Every user-facing string this phase ships. Author-authored heading text flowing into entry labels is content, not copy, and is out of scope here.

| Element | Copy |
|---------|------|
| Primary CTA | **No button CTA exists in this phase** — this is a read-only reading surface. The primary interactive affordance is the sidebar entry link, whose label is the author's heading text (sanitized to `strong`, `em`, `code` only) |
| Sidebar visible label | `Table of Contents` — exact, title case (D-05, user's explicit choice over "Contents" / "On this page") |
| Nav accessible name | `aria-label="Table of contents"` — exact string, **sentence case**, verbatim from A11Y-01. The case difference from the visible label is deliberate; both strings are locked as written |
| Permalink visible glyph | `#` (inside `<span aria-hidden="true">`) |
| Permalink accessible name | `Permalink to {heading text}` — heading text passed through `ERB::Util.html_escape` before interpolation |
| Empty state heading | **None — render nothing.** When the TOC is off, or fewer than 3 entries remain visible after hides, the sidebar, the grid wrapper, and the widened container are all absent (TOC-04, D-12: exactly 3 renders, 2 or fewer suppresses) |
| Empty state body | **None.** Do not ship "No sections found", "This post has no headings", or any placeholder. The reader must not learn that a feature was suppressed — TOC-04 says "no sidebar, no layout shift, no mobile dropdown" |
| Error state | **None.** There is no failure path: heading derivation is total, and a post with unparseable/absent headings simply yields zero entries, which routes to the suppressed branch above |
| Destructive confirmation | **None.** No destructive action in this phase |

**Do not add:** a "skip to content" link, a "back to top" control (POLISH-02, v2), a reading-time estimate (POLISH-05, v2), or numbered entries (POLISH-04, v2).

## Component Inventory

| Component | File | New/Modified | Contract |
|-----------|------|--------------|----------|
| TOC sidebar | `app/views/blogs/_toc_sidebar.html.erb` | **new** | `<div>` grid item wrapping `<nav aria-label="Table of contents">` → `<p>` label → `<ol role="list">` → `<li>` → `<a href="#toc-…">`. Renders only when `toc?` is true |
| Two-column wrapper | `app/views/blogs/show.html.erb` | **modified** | Conditional grid via **standalone `<% %>` ERB lines only** (Erubi `trim: true` emits zero bytes for the skipped branch). The existing `div.prose` line, its child line, and its closing line must stay **unmoved and unindented** |
| Article container | `show.html.erb` line ~28 + ~74 | **modified** | Branch-conditional class *segments* inserted inline, preserving surrounding literal text and the trailing `<%= '…' if @blog.spacing == 'relaxed' %>` exactly. TOC-off must render `class="prose prose-lg max-w-none mb-16 "` — **including the trailing space** `[VERIFIED: od -c on the golden fixture]` |
| Heading permalink | injected server-side into the same Nokogiri fragment | **new** | `<a class="toc-permalink" href="#{anchor}" aria-label="Permalink to …"><span aria-hidden="true">#</span></a>`, appended **after** `derive!` has captured entries |
| Permalink hover CSS | `app/assets/stylesheets/application.tailwind.css` | **modified (append)** | ~8 lines of plain CSS — a legitimate third narrow exception alongside `.tiptap-editor` and `.prose-paragraph-relaxed p`. Parent-hover reveal cannot be expressed in utilities without injecting `class="group"` onto author headings |

**`role="list"` on the `<ol>` is required** because `list-none` sets `list-style-type: none`, which drops list semantics in Safari/VoiceOver.

**DOM order:** the sidebar renders **before** the article in the DOM and is placed visually right via `lg:col-start-2 lg:row-start-1` — so screen-reader and keyboard users meet the TOC ahead of the article (WCAG 1.3.2 reading sequence). Do **not** use flexbox `order` to achieve this.

## Layout & Interaction States

| State | Contract |
|-------|----------|
| **TOC off** | Byte-identical to today. Golden-master spec passes without regenerating fixtures. `UPDATE_GOLDEN=1` is not a remedy |
| **TOC on, < 3 visible entries** | Same as TOC off — no sidebar, no grid wrapper, no container widening. Anchor `id`s **stay on the headings** so existing deep links keep resolving (D-11) |
| **TOC on, ≥ 3 visible entries, ≥ 1024px** | Two-column grid; sidebar sticky at `top-8`; article measure clamped at 65ch |
| **TOC on, < 1024px** | Sidebar is `hidden lg:block` — removed from layout *and* the accessibility tree. **No fallback list, no dropdown, no interim markup** (D-03). Phase 3 builds mobile disclosure as entirely new markup |
| **TOC entry rest** | gray-900 (H2) / gray-500 (H3), no underline |
| **TOC entry hover** | pink-600, `transition-colors` |
| **TOC entry focus-visible** | pink-600 **plus** a visible focus ring — keyboard parity with hover |
| **TOC entry active/current** | **Not in this phase.** Phase 3 owns `aria-current="location"` and its visual treatment |
| **Permalink rest** | `opacity: 0` — invisible in the default reading view |
| **Permalink hover (on parent heading) / focus-visible** | `opacity: 1`, 150ms ease-in-out fade |
| **Long TOC (> viewport height)** | `lg:max-h-[calc(100vh-4rem)] lg:overflow-y-auto` on the sticky element. Overflow on the *sticky element itself* is harmless; only clipping **ancestors** break stickiness |
| **Reduced motion** | `@media (prefers-reduced-motion: reduce)` disables the permalink opacity transition |

**Three sticky/grid mechanics that are non-negotiable** (each independently verified in RESEARCH):

1. `lg:self-start` on the sidebar grid item — without it, `align-items: stretch` makes the sidebar full row height and it can never travel. Silent failure.
2. `minmax(0,1fr)` for the article track — bare `1fr` floors at min-content and `<pre>`/`<table>` bodies will blow out the grid into horizontal page scroll.
3. No `overflow-hidden` / `overflow-x-hidden` anywhere in the ancestor chain — the chain is currently clean `[VERIFIED: grep]`; adding one silently kills sticky.

**Permalink is focusable** (Option (a) from RESEARCH Open Question 5), because D-15 specifies "hover/focus". Never combine `aria-hidden="true"` with the focusable `<a>` — `aria-hidden` belongs on the inner `<span>` carrying the `#` glyph only.

## Accessibility Contract

| Requirement | Phase 2 delivers | Deferred |
|-------------|------------------|----------|
| A11Y-01 | `<nav aria-label="Table of contents">` wrapper + `role="list"` | `aria-current` on the active entry → **Phase 3** (needs scroll-spy to know what "active" means). Mark A11Y-01 **partially** covered in traceability |
| INTX-04 | Focusable permalink with a descriptive accessible name | — |
| Keyboard | All TOC entries and permalinks reachable via Tab with visible `focus-visible` styling | Focus **management** on click (A11Y-02) → Phase 3 |
| Contrast | All declared pairs ≥ 4.5:1 (table above) | — |
| Reduced motion | Permalink transition disabled | Smooth-scroll gating (INTX-01) → Phase 3 |

**Do not add an `aria-label` to the site header `<nav>`** in `_navigation.html.erb`, even though two unnamed nav landmarks is a real (pre-existing) smell. That file renders on every page and any edit invalidates all five `*.page.html` golden masters. Log it as a separate quick task.

**`hidden lg:block` is the only server-renderable way** to satisfy D-03 — there is no viewport information at render time — and it does satisfy "no sidebar, no layout shift" because `display: none` removes the element from layout *and* the a11y tree.

## Out of Contract (explicit)

Named here so the executor does not "helpfully" ship them:

- Scroll-spy / active-entry highlighting / `aria-current` — Phase 3
- Smooth scroll, focus-on-click, sidebar auto-scroll to active entry — Phase 3
- Mobile "Contents" disclosure, any mobile TOC markup at all — Phase 3
- Admin toggle, relabel, reorder UI — Phase 4 (Phase 2 **reads** the `hidden` flag only, and casts it with `ActiveModel::Type::Boolean` rather than testing truthiness)
- Widening the *shared* container instead of branching it — ROADMAP criterion 3 names this exact failure mode
- Nested `<ol>` for H3 hierarchy — flat list with indent satisfies D-06; nesting is TOCV2-01
- Reading progress bar, back-to-top, print styles, numbered entries, reading time — all v2 POLISH
- Any change to `Blog::ALLOWED_TAGS` / `ALLOWED_ATTRIBUTES` — Phase 1 D-03 exists precisely to avoid it
