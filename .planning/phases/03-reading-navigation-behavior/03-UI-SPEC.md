# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** the **behavior layer** on the TOC-**on** blog show page — the active-entry (`aria-current`) visual treatment, the new mobile "Contents" disclosure, focus/motion semantics on jump, and sidebar containment. The TOC-**off** page is frozen by `spec/requests/blogs_golden_master_spec.rb` and this contract must not change a single byte of it (LAYOUT-03/LAYOUT-04). ## Visual Hierarchy

Phase 2's ordering rule stands unchanged and governs every decision below it:

1. **Primary (focal point): the article body.** Largest type (18px / 30px H2 / 24px H3), darkest text (gray-900, 17.4:1), widest track. Nothing in this phase may out-weight it.
2. **Secondary: the TOC — sidebar (desktop) and disclosure (mobile).** Deliberately quieter: 14–16px type, gray at rest, no surface on desktop.
3. **Tertiary: the permalink glyph.** `opacity: 0` at rest.

Phase 3 adds one new element to the ordering:

**Within the TOC (a secondary surface), the active entry is the loudest thing — but it never out-weights the article.** Exactly one entry carries the accent at any moment. A single 14–16px pink line item beside an 18px/30px gray-900 article does not invert the hierarchy; a column of pink links would, which is why Phase 2 correctly forbade resting-state accent and this phase does not relax that.

**The mobile disclosure is a control, not a panel.** Collapsed it is a 52px bordered bar above the article; opened it is a plain list on the page background. It gets a 1px hairline border (see Color) because a borderless "Contents ⌄" reads as a heading, and A11Y-03 requires "a real disclosure control". It gets no background fill, no shadow, and no elevation — those would make it a card competing with the article.

Use **`p-4`** instead: 16 + 20 (14px text at 1.43) + 16 = **52px** summary height, which also clears the 44×44px touch-target minimum (WCAG 2.5.5) with room to spare. `py-3` would land at exactly 44px with zero margin for error.

| Disclosure radius | `rounded-md` (6px) | Matches the existing share-button treatment in `show.html.erb` |

## Typography

**No new type tokens.** Every size and weight below already exists in the Phase 2 contract; this phase only assigns them to new elements.

| Role | Size | Weight | Line Height | Applies to |
|------|------|--------|-------------|------------|
| Label | 14px (`text-sm`) | 600 (`font-semibold`) | 1.43 (20px) | Sidebar label "Table of Contents" (inherited, uppercase `tracking-wide`) **and** the new disclosure trigger "Contents" (**title case, NOT uppercase** — see below) |
| Entry (H3) | 14px (`text-sm`) | 400 | 1.43 (20px) | Nested TOC entries in **both** the sidebar and the disclosure |
| Entry (H2) | 16px (`text-base`) | 400 | 1.5 (24px) | Top-level TOC entries in **both** the sidebar and the disclosure |
| Body | 18px | 400 | 1.7778 (32px) | Article body — **inherited unchanged** from `prose-lg` |

**The disclosure trigger is title case `Contents`, not uppercase.** It shares the 14px/600 token with the sidebar's eyebrow label but not its `uppercase tracking-wide` treatment: uppercase reads as a section eyebrow, and this element is an interactive control. Two different jobs, one type token.

**Font weight never changes on the active state.** `font-semibold` on the active entry would re-measure the label and can re-wrap a 2-line entry inside a fixed 256px track, making the whole sidebar twitch as the reader scrolls. The active state's two visual channels are **color + rail** (see Color). Any plan task that adds a weight swap to `aria-current` is out of contract.

**Article heading sizes are inherited, not redeclared** — same rule as Phase 2. This phase does not touch a single `font-size` in `div.prose`.

### Active-entry treatment (the one genuinely new visual decision in this phase)

| Channel | Rest | Active (`aria-current="location"`) |
|---------|------|-----------------------------------|
| Text color | gray-900 (H2) / gray-500 (H3) | **pink-600** (both levels) |
| Left rail | `border-l-2 border-transparent` | **`border-l-2 border-pink-600`** |
| Font weight | 400 | 400 — **unchanged** |
| Size / indent | unchanged | unchanged |

Implemented in the ERB as static classes plus a Tailwind attribute variant, so the Stimulus controller only ever writes/removes the `aria-current` attribute and never touches `classList`:

```
border-l-2 border-transparent transition-colors
aria-[current=location]:border-pink-600
aria-[current=location]:text-pink-600
```

**Why a rail and not color alone.** Active-section indication is information. Conveying it purely by hue fails WCAG 2.1 SC 1.4.1 (Use of Color) for readers who cannot distinguish pink from gray. The rail is a shape channel that survives greyscale and forced-colors mode (where `border-color` maps to a system color while author text colors are overridden). `aria-current` covers the programmatic channel; the rail covers the visual one.

⚠️ **AMENDS PHASE 2 — the rail costs an 18px left gutter on every entry, at rest.** The transparent rail must be reserved permanently or activation would shift the whole list sideways. Concretely, in `_toc_sidebar.html.erb` the `<li>` classes change from `""` / `"pl-4"` to `"border-l-2 border-transparent pl-4"` / `"border-l-2 border-transparent pl-8"`. Consequences the executor must accept: entries move 18px right inside the fixed 256px track (H2 labels 256 → 238px, H3 labels 240 → 222px), and D-06's **16px relative H3 nesting indent is preserved exactly** (32 − 16 = 16). This is TOC-on-only markup with **zero golden-master exposure**. **Confirm at the UI review gate** — it is two class strings and trivially reversible.

**Hover-on-active is intentionally indistinguishable** (both pink-600). Adding a distinct fourth colour to disambiguate a state the reader is already pointing at is noise.

**Contrast (verified, WCAG 2.1 AA):**

| Pair | Ratio | Verdict |
|------|-------|---------|
| pink-600 `#db2777` on white | 4.60:1 | PASS — covers the active entry at both 14px and 16px (normal text ≥ 4.5:1) |
| gray-900 `#111827` on white | 17.4:1 | PASS — resting H2 entries, "Contents" trigger label |
| gray-500 `#6b7280` on white | 4.83:1 | PASS — resting H3 entries |
| pink-600 rail on white | 4.60:1 | PASS — exceeds the 3:1 non-text/UI-component minimum (SC 1.4.11) |
| gray-200 `#e5e7eb` disclosure border on white | 1.24:1 | **Decorative only — not a required contrast pair.** The control's boundary is not the only affordance: the "Contents" label (17.4:1), the chevron (17.4:1), and the native `DisclosureTriangle` AX role all identify it. Do **not** darken it to gray-400 to "fix" contrast — that would out-weight the article's own `border-gray-200` hairlines |

## Icon Contract

Exactly **one** icon ships in this phase. Copy this markup verbatim — it is the codebase's existing heroicons-outline chevron-down from `app/views/shared/_navigation.html.erb:20-22`, with the state and motion variants added:

```html
<svg class="w-4 h-4 shrink-0 transition-transform group-open:rotate-180 motion-reduce:transition-none"
     fill="none" stroke="currentColor" viewBox="0 0 24 24" aria-hidden="true">
  <path stroke-linecap="round" stroke-linejoin="round" stroke-width="2" d="M19 9l-7 7-7-7"/>
</svg>
```

- `aria-hidden="true"` is **mandatory** — the `<summary>` already exposes `expanded` in the accessibility tree [VERIFIED: RESEARCH Pattern 4, CDP AX dump: `{focusable: true, expanded: false}` → `{expanded: true}`]. An unhidden icon would double-announce.
- `group-open:rotate-180` requires `class="group"` on the `<details>` element. [VERIFIED: `open` variant present in the installed `tailwindcss@4.1.14` build]
- `motion-reduce:transition-none` is required — the rotation is decorative motion.
- `stroke="currentColor"` means the chevron inherits gray-900 from the `<summary>`; do **not** give it its own colour.

**Do not add:** a hamburger, a "list"/bars icon beside the label, a per-entry bullet or arrow, or a second icon of any kind.

## Copywriting Contract

Every user-facing string this phase ships. Author-authored heading text flowing into entry labels is **content**, not copy, and is out of scope here.

| Element | Copy |
|---------|------|
| Primary CTA | **`Contents`** — the `<summary>` trigger label. Exact string, title case, locked by D-07 (user's explicit wording, matching the roadmap's "tappable Contents disclosure"). It is deliberately **not** the desktop sidebar's "Table of Contents"; Phase 2 D-05 already established the two labels are independent |
| Trigger label when scrolled | **`Contents` — unchanged.** D-08: the trigger never shows the active section name. Scroll-spy state and the (possibly collapsed) trigger stay decoupled |
| Mobile nav accessible name | `aria-label="Table of contents"` — the same exact sentence-case string as the desktop nav, verbatim from A11Y-01. Safe to duplicate: the two navs are `lg:hidden` / `hidden lg:block`, so `display: none` keeps exactly one of them in the accessibility tree at any viewport |
| Active-entry announcement | **`aria-current="location"` and nothing else.** Do **not** ship a visually-hidden "(current section)" / "You are here" string — `aria-current` is the standard mechanism and screen readers already announce it. `location` over `page`: `page` is defined as "the current page within a set of pages", which is wrong for same-page anchors [CITED: MDN aria-current] |
| Empty state heading | **None — render nothing.** Unchanged from Phase 2: TOC off, or fewer than 3 visible entries, renders no sidebar, **no disclosure**, and no `data-controller="toc"` wrapper |
| Empty state body | **None.** No "No sections found", no placeholder. The reader must not learn a feature was suppressed (TOC-04) |
| Error state | **None — and this is a real decision, not an omission.** There is no failure path that needs copy. With JS disabled or broken: `<details>` still opens and closes natively, entry links still perform a native fragment jump, and `scroll-mt-8` still lands the heading at 32px [VERIFIED: RESEARCH — native fragment navigation honors `scroll-margin-top`]. The reader loses smooth scroll, focus move, and highlighting — never the ability to navigate. Do **not** ship a `<noscript>` banner |
| Destructive confirmation | **None.** No destructive action in this phase |

**Do not add:** "On this page", "Jump to section", "In this article", "Back to top" (POLISH-02, v2), a reading-progress label (POLISH-01, v2), reading time (POLISH-05, v2), or numbered entries (POLISH-04, v2).

Zero classes → zero visual effect. Opened/closed with standalone `<% %>` ERB lines inside the existing `if article.toc?` branch, so Erubi `trim: true` emits **zero bytes** on the TOC-off path |
| Mobile disclosure | `app/views/blogs/_toc_disclosure.html.erb` | **new** | `<details class="group lg:hidden mb-8 rounded-md border border-gray-200">` → `<summary class="list-none [&::-webkit-details-marker]:hidden cursor-pointer p-4 flex items-center justify-between text-sm font-semibold text-gray-900 focus-visible:ring-2 focus-visible:ring-inset focus-visible:ring-pink-600">Contents` + chevron → `<nav aria-label="Table of contents" class="px-4 pb-4">` → `<ol role="list" class="list-none space-y-2 pl-0">` → `<li>` → `<a href="#toc-…">`. **Closed by default** (no `open` attribute), on every load including `#anchor` deep links |
| TOC sidebar | `app/views/blogs/_toc_sidebar.html.erb` | **modified** | Adds `data-toc-target="sidebarScroller"` + `lg:scroll-py-4` to the existing scroll container; `data-toc-target="link"` to each `<a>`; the rail classes + `aria-[current=location]:*` variants to each `<li>`/`<a>`. **No structural change** — same `nav > p > ol > li > a` tree |
| TOC controller | `app/javascript/controllers/toc_controller.js` | **new** | Toggles `aria-current` and calls scroll/focus APIs **only**. **Never** writes `innerHTML`, `insertAdjacentHTML`, or `classList` (see Registry Safety) |

**`role="list"` on both `<ol>`s is required** — `list-none` sets `list-style-type: none`, which drops list semantics in Safari/VoiceOver. Same rule Phase 2 applied to the sidebar.

**Both `<summary>` marker-suppression classes are required.** `list-none` hides the native triangle in Chrome/Firefox; Safari needs `[&::-webkit-details-marker]:hidden`. The chevron is the mandated replacement indicator — **do not remove the marker without it**, because Firefox + VoiceOver leans on triangle direction for state. [CITED: scottohara.me/blog/2022/09/12/details-summary.html]

**DOM order:** disclosure → sidebar → article. The disclosure precedes the grid so it reads above the article at every width; the sidebar keeps Phase 2's before-the-article DOM position with `lg:col-start-2 lg:row-start-1` visual placement (WCAG 1.3.2). Do **not** use flexbox `order`.

**Two link sets exist — resolve the active entry by anchor, never by index.** ⚠️ RESEARCH Pattern 2's `this.linkTargets[index]` assumes one link per heading. With the disclosure rendered, `linkTargets` holds **2N** links. The contract: match links by their resolved `hash`/anchor and set `aria-current="location"` on **every** link pointing at the active heading (one per nav). This is not a duplicate-`aria-current` violation — the two navs are separate sets and only one is ever in the accessibility tree.

## Layout & Interaction States

| State | Contract |
|-------|----------|
| **TOC off** | Byte-identical to today. No wrapper, no `data-controller`, no disclosure, no controller instance. Golden-master spec passes without regenerating fixtures; `UPDATE_GOLDEN=1` is not a remedy |
| **TOC on, < 3 visible entries** | Same as TOC off. Anchor `id`s stay on the headings so existing deep links keep resolving (Phase 2 D-11) |
| **≥ 1024px (`lg`)** | Sidebar visible, sticky at `top-8`. Disclosure `display: none` — out of layout **and** out of the a11y tree |
| **< 1024px** | Disclosure visible above the article, **collapsed**. Sidebar `display: none`. Scroll-spy still runs and still marks `aria-current` on the hidden disclosure links (correct on open) |
| **Entry rest** | gray-900 (H2) / gray-500 (H3), no underline, transparent 2px rail |
| **Entry hover** | pink-600 text, `transition-colors`. Rail stays transparent |
| **Entry focus-visible** | pink-600 text **plus** the existing `ring-2 ring-pink-600 ring-offset-2` |
| **Entry active** | pink-600 text **plus** pink-600 rail, weight unchanged (see Color) |
| **Active at page top** | First entry active before any scroll (D-02) — the TOC is never in a nothing-highlighted state |
| **Active at page bottom** | Last entry active once the page bottom is reached, even if that section never crosses the trigger line (D-03). Empirically necessary, not defensive: measured 3-of-4 without it |
| **Active on `#anchor` load** | Computed synchronously in `connect()` from `location.hash` **before** any observer/scroll event, so there is no visible flash of "first entry active" (D-04) |
| **Jump — motion** | `scrollIntoView({behavior: 'smooth', block: 'start'})`. Duration is browser-controlled; **do not** hand-animate a custom easing or duration |
| **Jump — reduced motion** | `behavior: 'auto'` (instant), read from `matchMedia('(prefers-reduced-motion: reduce)')` **at click time**, not cached at connect. Gates the chevron rotation too via `motion-reduce:transition-none` |
| **Jump — landing** | Heading lands **32px** from the viewport top via the inherited `prose-headings:scroll-mt-8`. The site header is `position: relative`, `h-16`, **not sticky** (Phase 2 D-07) — no header-height compensation. Do **not** add a JS `scrollBy` offset |
| **Jump — focus** | Keyboard focus moves to the target heading (A11Y-02) via Turbo's transient add-`tabindex`/focus/remove-`tabindex` pattern, with `focus({preventScroll: true})` **before** `scrollIntoView` so the focus call does not cancel the animation |
| **Heading focus ring** | **No custom style, and no `outline: none`.** Programmatic `.focus()` does not trigger `:focus-visible` in Chrome, so nothing paints in practice; if a browser does paint a native ring, that is correct and must not be suppressed |
| **Long TOC (> viewport)** | Sidebar scrolls internally within the existing `lg:overflow-y-auto` container. `scrollIntoView({block: 'nearest'})` on the active link, with `lg:scroll-py-4` (16px) so the active entry is never flush against the container edge. **Never** `behavior: 'smooth'` here — it competes with the page's own smooth scroll during a jump. Measured: `window.scrollY` unchanged at 4000 before and after |
| **Disclosure open** | Chevron rotates 180°, panel expands in place, article is pushed down (no overlay — a floating/overlay TOC is explicitly Out of Scope in REQUIREMENTS.md) |
| **Disclosure — entry selected** | Auto-closes (`open = false`) **and** focus goes to the target heading, not back to the trigger (D-09 + D-10) |
| **Disclosure — Escape** | Closes and returns focus to `<summary>` (D-11). Escape is a pure cancel and must **never** send focus to a heading |
| **Disclosure — Tab while closed** | Focus skips the collapsed links entirely — native `<details>` content inertness, no `inert`/`tabindex` wiring needed [VERIFIED: measured, Tab from `<summary>` goes to `BODY`] |
| **No JS** | `<details>` toggles natively, links jump natively, `scroll-mt-8` still applies. Degraded, never broken |
| **Turbo navigation** | Observer disconnected, scroll listener removed, state cleared in `teardown()`/`disconnect()`. Repeated visits leave nothing running |
| **Page-level scroll** | `scroll-behavior` on `html`/`body` stays `auto`. Setting it to `smooth` is forbidden by success criterion #5 and would make the reduced-motion gate meaningless |

**The capture-phase handler also intercepts Phase 2's `.toc-permalink` links — this is intentional and in-contract.** The wrapper contains `div.prose`, so `a[href^="#"]` matches permalinks too. They therefore gain the same reduced-motion-gated smooth scroll, 32px landing, focus move, and `aria-current` update as TOC entries. Zero visual change to the permalink itself, and it repairs the permalink's post-Turbo-navigation breakage as a free side effect without editing `_navigation.html.erb`.

**Do not fix the legacy `_navigation.html.erb` smooth-scroll handler in this phase.** Capture-phase `stopPropagation()` neutralises it for TOC clicks with no edit to that file — and that file renders on every page, so any edit invalidates all five `*.page.html` golden masters. Track it separately. [RESEARCH Open Question 1]
